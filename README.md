# 🎵 MuseNest (Версия 0.1 - Минимально Рабочая)

Мощный кроссплатформенный инструмент для автоматического мониторинга дискографий любимых артистов в музыкальных базах данных (**Deezer**, **Spotify**, **MusicBrainz**, **Яндекс Музыка**, **Zvuk**), умного поиска лучших аудиозаписей на **YouTube** (с фильтрацией по длительности, стоп-словам) и локальной загрузки в **MP3** высокого качества.

---

## 🚀 Нововведения в Версии 0.5.22 (Лог Изменений)

* **Исполнитель (трек, альбом) пишется в МЕТАДАННЫЕ mp3.** Конвертер стирал
  все теги (`-map_metadata -1`), и плееры показывали файл без исполнителя.
  Теперь каждый скачанный файл получает ID3-теги: «Исполнитель» — мониторимый
  артист, «Название» — трек, «Альбом» — альбом (v2.3, читается всеми
  плеерами). Не имя файла, а именно теги.
* **Прогон по всем существующим**: при старте приложения и в начале каждого
  скана библиотека приводится к тегам — сначала записи БД (артист + трек +
  путь), затем обход папки сохранения по структуре `Жанр/Артист/Альбом/
  Трек.mp3` (для файлов, которых нет в базе). Уже правильно тегированные
  файлы пропускаются без перезаписи, так что повторные прогоны дёшевы.
* Тегирование никогда не ломает загрузку: любые проблемы — только в лог
  («🏷️ Прогон тегов: записано N, уже с тегами M, ошибок K»).

## 🚀 Нововведения в Версии 0.5.21 (Лог Изменений)

* **Адаптивный интервал стал линейным — по обратной связи.** Экспонента
  (×2/÷2) для фоновой загрузки не подходит: шаг теперь **+3 с за каждую
  ошибку** (1.5 → 3 → 6 → 9 → 12 → … → потолок 60 с) и **−3 с после каждых
  10 успешных скачиваний**, вплоть до базы 1.5 с. Мягче растёт, быстрее
  возвращается, скачивание в фоне не проваливается в долгие паузы.

## 🚀 Нововведения в Версии 0.5.20 (Лог Изменений)

* **Адаптивные интервалы запросов к Zvuk.** Базовая пауза (1.5 с) была
  статичной — при непрерывной загрузке антибот срабатывал «каждые несколько
  треков». Теперь **каждый** 418/429 удваивает интервал между запросами
  (1.5 → 3 → 6 → 12 → 24 → 48 → **потолок 60 с** — на нём, по проверке на
  практике, загрузка продолжается стабильно), а **10 чистых запросов подряд**
  откатывают интервал вниз вдвое, к базе. Действует на все запросы к
  zvuk.com — и поток, и метаданные (общий шлюз). Рядом с охладительным
  режимом 0.5.18 это даёт два эшелона: мгновенная пауза 15–60 с при блоке +
  долговременное разрежение потока запросов, чтобы блоки перестали
  повторяться.
* Тесты детерминированы: гейт пейсинга в стендах без джиттера (был флейк
  «первый запрос без долга»).

## 🚀 Нововведения в Версии 0.5.19 (Лог Изменений)

* **Зона каналов видит вкладку «Релизы» — там, где у артист-каналов лежат
  треки.** Раньше извлекалась только вкладка «Видео»: у типовых артист-каналов
  она почти пуста, а треки живут в «Релизах» как альбомные плейлисты — зона
  выходила пустой. Теперь сканируются обе вкладки, альбомные карточки
  (OLAK5uy_…) раскрываются в треки; лимиты: ≤100 карточек на канал, ≤40
  раскрытых альбомов, ≤300 треков на альбом, всё кэшируется на 30 минут.
* **Ссылка вида `youtube.com/@handle/releases` принимается**: суффиксы
  вкладок (`/releases`, `/playlists`) больше не ломают разбор — раньше такая
  ссылка молча выпадала из зоны (и при заданных каналах глобальный fallback
  запрещён → «ничего не найдено»).
* **Исправлен «exact-бонус» матчера зоны**: бонус за точное совпадение
  сравнивал отсортированные токены лексикографически, из-за чего точный
  трек получал 0, а соседние названия — максимум. Теперь бонус даётся, когда
  все слова трека присутствуют в заголовке (как и задумано).

## 🚀 Нововведения в Версии 0.5.18 (Лог Изменений)

* **Антибот Zvuk: глобальный «охладительный» режим вместо долбёжки.**
  Реальный лог: 418 на все три попытки — блок Zvuk держится десятки секунд,
  а короткие автоповторы лишь продлевали его. Теперь при любом 418/429
  **весь процесс** уходит в общую паузу (эскалация 15 → 30 → 60 с; после
  успешного запроса сброс, после 5 минут тишины эскалация стартует заново):
  повтор происходит после того, как блок истёк, а не сквозь него. Все
  вызовы метаданных (клиент zvuk-music: поиск, альбомы, треки) теперь тоже
  проходят через общий пейсинг — раньше они били в API без пауз и
  провоцировали блок, который потом бил по загрузкам.
* В логе видно работу механизма: «⏳ Антибот Zvuk: пауза 15 с перед
  повтором (блок действует на все запросы)».

## 🚀 Нововведения в Версии 0.5.17 (Лог Изменений)

* **Папки-аккордеоны работают каждая сама за себя.** Ключ раскрытия папки
  строился заменой «всё, кроме латиницы и цифр» на «_»: две кириллические
  папки одинаковой длины («Рок» и «Поп») получали **одинаковый** ключ и id,
  поэтому клик по любой папке открывал/закрывал только первую. Ключ теперь

* **Выпадающее окно каналов больше не перекрывается панелями-фильтрами.**
  Каждая колонка — свой stacking context (backdrop-filter), и колонка
  «Black-list фильтры», нарисованная позже, накрывала выпавшую панель
  каналов, выходящую за границу своей колонки. Колонка с открытым
  дропдауном (или подсказками поиска) теперь поднимается над соседями,
  а сама панель ограничена по высоте с прокруткой.

 что делать.
* **Повтор поиска при возврате фокуса.** Окно добавления артиста при
  получении фокуса само повторяет поиск по уже введённому тексту — больше
  не нужно стирать символ и вводить заново, чтобы вернуть подсказки.

## 🚀 Нововведения в Версии 0.5.15 (Лог Изменений)

* **Добавление из поиска работает всегда — даже во время скана и даже после
  падения скана.** Скан не имел `try/finally`: любое неожиданное исключение
  оставляло флаг «скан идёт» включённым навсегда, а задача разрешения
  артиста (0.5.14) в этом случае ждала окончания «скана» целый час — artista
  не появлялись в библиотеке. Теперь: `run_scan` гарантированно сбрасывает
  флаг в `finally`; задача разрешения **не ждёт** — она безопасно выполняется
  параллельно со сканом (фаза записи атомарна: перечитывание библиотеки и
  объединение под обоими замками, синхронизация скана не теряется).
* **Мусорные строки artists.txt больше не становятся «артистами-призраками».**
  Строки-ссылки, которые не удалось разобрать (например, ссылки на Zvuk из
  старых версий), не импортируются как артисты; совпадающие по имени записи
  (даже в разном регистре) не дублируются.

## 🚀 Нововведения в Версии 0.5.14 (Лог Изменений)

* **Добавление артистов больше не «умирает» после нескольких добавлений, и
  артисты не перестают мониториться.** Найдены и устранены три корневые
  причины:
  * `load_config` пересобирал список артистов **из artists.txt**: при
    совпадении имён артист молча выпадал из конфига, а каждый цикл
    сохранения/загрузки стирал метаданные (каналы 📺, папки, id). Теперь
    `config.json` — основной источник: артисты из него сохраняются целиком,
    а txt только **дополняет** список новыми строками (ручные правки файла).
  * `update_library_metadata` держала глобальный lock все долгие минуты
    сетевой загрузки — скан упирался в неё и «замирал» (артисты переставали
    обновляться альбомами). Lock теперь берётся только на короткую фазу
    записи; библиотека перед записью перечитывается, обновление пишется
    по-артистно — данные синхронизации скана не затираются; каналы 📺
    переживают полное обновление; артисты, убранные из конфига, уходят из
    библиотеки при полном обновлении (как раньше).
  * `/api/library/update` отвечал `409 Scan already running` во время скана —
    добавленные в это время артисты навсегда оставались «⏳ добавление…».
    Теперь задача становится в очередь и **ждёт окончания скана** (с
    ограничением по времени), затем артист разрешается.
* **Понятный отклик при дубликате**: попытка добавить артиста, который уже
  есть в списке, показывает «ℹ️ уже есть в списке» вместо молчаливого
  ничего-не-происходит.

## 🚀 Нововведения в Версии 0.5.8 (Лог Изменений)

* **Антибот-защита Zvuk больше не роняет треки (HTTP 418).** При параллельной
  загрузке часть треков падала с «Zvuk не отдал поток… HTTP 418», а часть
  скачивалась: 418 — это антибот-ответ Zvuk на анонимные запросы, идущие

  418/429 повторяется с нарастающей паузой (две попытки) — такие отказы почти
  всегда временные. Если не помогло даже это, в логе честно: «сработала
  антибот-защита… подождите пару минут или добавьте токен».

## 🚀 Нововведения в Версии 0.5.6 (Лог Изменений)

* **Роутер запросов YouTube (антиблокировка).** Реальный скан получил от
  YouTube блокировку сессии на час: `This content isn't available, try again
  later. The current session has been rate-limited...` Причина — потоки не
  только искали, но и *скачивали* параллельными сессиями yt-dlp, а общий
  «rate limiter» спал прямо внутри блокировки, выстраивая все запросы в одну
  ленту. Теперь так, как просили: **потоки ищут одновременно, а скачивают по
  очереди** — поиски идут параллельно с лёгким разнесением старта
  (`search_delay_sec`, по умолчанию 1 с), а каждая загрузка YouTube сначала
  берёт слот в глобальной очереди (`download_max_parallel`, по умолчанию **1**
  — строго одна загрузка за раз) и минимальную паузу между стартами
  (`download_delay_sec`, по умолчанию 3.5 с + случайный джиттер). Очередь
  загрузок не блокирует поиски и наоборот; «Стоп» снимает ожидание очереди;
  ожидание дольше 2 секунд пишется в лог строкой «⏳ Антиблокировка: загрузка
  ждала своей очереди…». В настройках появились плитки **«Загрузок
  одновременно»** и **«Пауза между загрузками»**.
* **Чистые тексты ошибок yt-dlp.** ANSI-коды цвета (`[0;31mERROR:[0m`)
  вычищены из сообщений об ошибках загрузки и поиска — в логе и в
  library.json теперь читаемый текст.

## 🚀 Нововведения в Версии 0.5.5 (Лог Изменений)

* **«Источник: Авто» теперь правда следует за общим источником.** Интерфейс
  проставляет каждому артисту `source: "auto"`, но раньше эта строка уходила в
  построитель источника как есть: при общем источнике Zvuk артисты всё равно

  ошибкой 400, если ключи Spotify не заполнены. Теперь `auto` (и пустое
  значение) во всех местах — сканирование, библиотека, форс-загрузка, поиск
  артистов — разворачивается в текущий `music_source`, а явный выбор артиста
  по-прежнему побеждает общую настройку.
* **Свой id артиста — только для своего источника.** При `music_source=zvuk`
  сканер брал первый попавшийся id из карточки артиста (обычно Spotify base62)
  и нёс его в Zvuk: источник не мог разрешить такой id, скан падал с
  «Artist ID not found». Теперь при известном приоритете сначала используется
  `zvuk_id`/`deezer_id`/`spotify_id`/`yandex_id` **того самого** источника; если
  своего id нет — источник ищет артиста по имени, и только когда поиск не дал
  ничего, чужой id используется как последняя надежда.
* **Поиск артистов ходит в настроенный источник первым.** `search_artists`
  жёстко задавал порядок Spotify → Deezer → Spotify → MusicBrainz, поэтому
  Zvuk и Яндекс в поиске не участвовали вовсе. Теперь первым спрашивается
  приоритетный источник, остальные подключаются как фолбэк; Zvuk и Яндекс
  доступны и в диалоге «добавить артиста».
* **Форс-загрузка распараллелена.** «Скачать принудительно» обрабатывало
  треки строго по одному. Теперь треки расходятся по потокам
  `download_threads` (те же, что в сканировании), каждый поток показывает
  своё задание в панели потоков, порядок результатов в ответе API сохраняется,
  а кнопка «Стоп» снимает ещё не начатые задачи.
* **Скан больше не падает на артистах-строках.** Артист, сохранённый в
  конфиге просто строкой (без карточки), обрывал сканирование с ошибкой
  `'str' object has no attribute 'get'` — обработан отдельно.

    значит дело в сети/прокси/DNS, а не в токене;
  * токен активен → «токен активен, качество: high».
* В результат добавлены поля `api_status` и `token_status` (HTTP-коды) для точной диагностики.
* **Тесты**: `tests/test_zvuk_downloader_check.py` — 8 проверок, включая ключевую регрессию
  (401 на токене ≠ «API недоступен»), настоящую аварию сети и `503` от сервера.

## 🚀 Нововведения в Версии 0.3.2 (Лог Изменений)

* **Zvuk больше не падает на весь трек, если высокое качество недоступно**: раньше
  `get_stream_url()` запрашивал `high` и при отказе молча возвращал `None`, из-за чего
  трек уходил на YouTube. Теперь работает **лесенка качества**: запрошенное (`high`/`flac`)
  → `mid`, то есть трек скачивается напрямую с Zvuk в доступном качестве, а в лог пишется
  предупреждение «отдано в качестве 'mid' вместо 'high'».
* **Истёкший токен больше не роняет загрузку**: на `HTTP 401` код повторяет запрос
  с анонимным токеном, а последующие ступени качества сразу идут с анонимным — протухший
  токен не отправляется повторно (меньше лишних запросов и риска лимитов).
* **Скачивание идёт тем же токеном, который отдал поток**: если поток получен анонимно,
  файл тянется анонимным токеном, а не истёкшим пользовательским.
* **Честные сообщения об ошибках вместо угадывания**: прежний текст
  «Без токена доступен только анонимный mid — этот трек требует подписку» был захардкожен
  и **врал**, когда токен задан (а качество `high` выбирается именно при заданном токене).
  Причина проглатывалась в `except Exception: return None`. Теперь ошибка содержит реальные
  коды и трассу попыток, например:
  `Токен Zvuk истёк или неверен (HTTP 401)… Пробовал: high (токен) → HTTP 401; high (аноним) → HTTP 403; mid (аноним) → ok. Токен задан.`
  Отдельно различаются: истёкший токен (401), отказ подписки/региона (403),
  сеть/прокси/DNS (нет ни одного ответа), и «200 без поля `stream`» — с показом формы ответа.
* **Токен не попадает в логи**: значение `X-Auth-Token` намеренно не кладётся в трассу
  попыток (проверяется отдельным тестом).
* **Строка лога остаётся читаемой**: сырой текст `requests` при сетевом сбое
  (`HTTPConnectionPool(...) Max retries exceeded ...`) сворачивается в короткую метку —
  «нет соединения» / «таймаут» / «DNS не резолвится» / «прокси не отвечает» / «ошибка TLS»,
  а причина называется один раз, а не по разу на каждое качество:
  `Zvuk недоступен (нет соединения) — до /api/tiny/track/stream не дошёл ни один запрос. Пробовал качества: high, mid. Токен задан.`
  Полный текст сохраняется в `ZvukStreamError.detail` для отладки.
* **Понижение качества видно в логе**: если запрошен `high`, а отдан `mid`, пишется
  предупреждение с именем артиста/трека и обоими качествами.
* **Тесты**: `tests/test_zvuk_stream.py` — 21 проверка на локальном стенде, отвечающем как
  Zvuk (401/403/200 без `stream`), включая точный сценарий из лога
  (`id=3862635281`, `quality=high`), отсутствие утечки токена и ограничение длины строки лога.
  Отдельно проверяется, что **сам файл** качается рабочим токеном: после восстановления по
  анонимному токену на загрузку аудио уходит именно он, а не протухший пользовательский
  (иначе фикс был бы косметическим — `resolve_stream` восстанавливался бы, а скачивание
  снова падало на 401).
  `tests/test_monitor_zvuk_downgrade.py` — 6 проверок предупреждения о понижении качества.

  * **Парсер свободных файлов**: Если треки были просто навалены в кучу в папку жанра в формате `Артист - Трек.mp3`, система выделит имя исполнителя, найдет его в Deezer, добавит в настройки и автоматически расставит все файлы по аккуратным вложенным полочкам.
* **Современные пилюли-игноры (Pill Buttons)**: Архаичные чекбоксы заменены на элегантные овальные бейджи. Они имеют деликатный темный стиль, а при активации подсвечиваются ярким неоново-красным цветом. Клик по игнору больше никогда не вызывает спонтанного закрытия/сворачивания карточки артиста!
* **Монолитный вложенный дизайн медиатеки**: Карточка артиста представлена как целостная плитка с мягким темным фоном. Раскрытие альбомов происходит физически **внутри карточки** на контрастном фоне. Слева от каждого альбома горит цветная акцентная полоса, отражающая статус готовности.
* **Светодиодный (LED) статус треков**: Каждая песня лишилась громоздких рамок и выводится в виде плоской интерактивной строки, перед которой горит яркий неоновый светодиод: 🟢 (Скачано), 🔴 (Ошибка/Пропуск), ⚪ (Ожидание). Текст трека окрашивается в тон его статусу.
* **Стабильное копирование логов**: Клик по строке логов мгновенно копирует ее в буфер обмена. На правом краю строки парит абсолютный бейдж **`Copied!`**. Копирование защищено от прерываний — даже при получении десятков новых логов в секунду, подсветка и бейдж удерживаются ровно 1.2 секунды!
* **Устранение миганий (Differential DOM)**: Как для логов, так и для дерева библиотеки внедрена технология сверки HTML-снимков. Контент в DOM перезаписывается только при реальном изменении данных, полностью убирая мерцание и сохраняя позицию прокрутки.
* **Абсолютное выравнивание в поиске**: Сетка выпадающего окна поиска переведена на Flexbox. Имена артистов выровнены слева, а подписчики, ID и интерактивные круглые кнопки 🎧 прижаты к правому краю, образуя идеальную вертикальную колонку.
* **Плиточный дашборд настроек (2х2)**: Настройки интервала, допуска, потоков и лимитов оформлены в виде крупных отзывчивых карт. Рамка карты мягко подсвечивается зеленым неоновым свечением при наведении, а вся плитка является кликабельной интерактивной кнопкой! В выпадающих списках устранен белый текст на белом фоне.

## ✨ Ключевые возможности

1. 📁 **Структурированный формат папок («Жанр / Артист / Альбом / Трек.mp3»):**
   - Автоматическая структуризация музыкальной коллекции по вложенным папкам жанров и альбомов.
   - Имена файлов и папок бережно очищаются от запрещенных операционной системой символов.

2. 🧠 **Умная дедупликация и экономия места (100% защита от дубликатов):**
   - **Один трек — один файл на диске:** Если трек присутствует и в сингле, и в полноценном альбоме, он скачивается **ровно один раз** в папку первого полноценного альбома.
   - **Логические ссылки:** В интерфейсе этот трек будет светиться зелёным (скачанным) во всех альбомах и синглах, где он присутствует, не занимая лишнего места на диске.
   - **Авто-сортировка и чистка:** Скрипт автоматически находит старые файлы (в корне или папках синглов), переносит их в новые папки альбомов, а опустевшие папки синглов удаляет.
   - **Решение проблемы маятника:** Логика приоритетов построена по нормализованному имени трека, что исключает бесконечный перенос файлов туда-сюда из-за разных ID релизов на сервисах.

3. 🚀 **Многопоточность нового поколения:**
   - **Параллельная загрузка:** Поиск на YouTube и скачивание треков выполняются параллельно (до 8 потоков в соответствии с настройками).
   - **Параллельный сканер (в 6 потоков):** Сбор треков и альбомов из сети Deezer/Spotify оптимизирован через пул потоков, благодаря чему дискография любого артиста собирается за 1–2 секунды вместо полуминуты.

4. 🌍 **Полная расширяемая локализация (RU / EN / Кастомные языки):**
   - Удобный выпадающий список выбора языков прямо в шапке интерфейса (выбор запоминается в браузере).
   - Все тексты (включая настройки, источники, плейсхолдеры и логи) полностью переведены.
   - **Кастомные переводы:** Пользователи могут самостоятельно создавать новые локализации, просто скопировав любой файл в `data/translations/` (например, создав `DE-Deutsch.txt`).
   - **Каскадный фоллбэк:** Если в пользовательской локализации пропущен какой-то ключ, интерфейс автоматически и безопасно подставит английский вариант — никаких пустых строк или ошибок в UI.

5. 🔴 **Интерактивная диагностика ошибок (`ERR-1` — `ERR-5` + подробный TODO-лист):**
   - Если трек не прошел фильтры, он загорается **тонкой красной обводкой** с кодом ошибки:
     - **`ERR-1`** — Не найдено подходящих результатов на YouTube.
     - **`ERR-2`** — Не подошло по времени (длительность отличается от оригинала больше допуска).
     - **`ERR-3`** — Отфильтровано стоп-листом блек-листа.
     - **`ERR-4`** — Ошибка загрузки или конвертации (обрыв соединения, блокировка YouTube).
     - **`ERR-5`** — Сетевой сбой или жесткий лимит запросов YouTube.
   - **Всплывающий TODO-список:** При наведении курсора на код ошибки выводится подробная пошаговая инструкция на выбранном языке, как решить эту конкретную проблему.

6. ⏹ **Экстренная мгновенная остановка:**
   - Прерывание текущего сканирования и загрузок в один клик. Работает молниеносно благодаря перехватчику логов `YtDlpAbortLogger` и progress-hook, выбрасывающим прерывание прямо внутри `yt-dlp`.

## 🛠️ Техническое описание архитектуры (для будущих разработчиков)

Инструмент построен по модульному принципу на связке **Flask (бэкенд)** и **Vanilla JS (фронтенд)**.

### 1. Архитектура работы с источниками (`core/source.py`, `core/spotify.py`)
- **`DeezerSource`**: Не требует авторизации. Использует общедоступное API `https://api.deezer.com`. Служит основным стабильным поисковым шлюзом по умолчанию. Извлекает число подписчиков (`nb_fan`).
- **`SpotifyClient`**: Работает через официальное API `https://api.spotify.com/v1`. Требует выполнения OAuth Client Credentials (`_auth()`). Если авторизация падает с ошибкой (например, из-за пустых/неверных ключей), это перехватывается на уровне роутера API и не приводит к падению бэкенда.
- **`MultiFallbackSource`**: Умный агрегатор источников. Сначала опрашивает Spotify (если авторизован), затем Deezer, и в крайнем случае — базу MusicBrainz.

### 2. Спецификация хранения артистов (`data/config.json` и `data/library.json`)
В версии 0.1.7 каждый артист в конфигурационном файле имеет следующую структуру:
```json
{
  "id": "spotify_id_или_deezer_id_или_имя",
  "name": "Официальное имя артиста",
  "source": "deezer",  // Источник для мониторинга: "spotify" или "deezer"
  "spotify_name": "Имя в Spotify", 
  "spotify_id": "46P740d5P5uXbS6nCq0lS7", // Уникальный 22-значный Base62 ID
  "deezer_id": "15100095",                // Числовой ID Deezer
  "genre_path": "Rock/Metal"              // Опциональный путь подпапок
}
```

Файл `library.json` хранит в себе снимок структуры дискографии артистов (альбомы, треки, длительность, флаги `downloaded`, `ignored`, `no_match` и коды ошибок `error_code`), которая динамически обновляется из выбранного источника.

### 3. Логика API Поиска (`/api/artist_search`)
Когда пользователь отправляет поисковый запрос:
1. Выполняется парсинг ввода (`src_mod.parse_input`). Распознаются регулярными выражениями ссылки Spotify, Deezer, чистые Spotify ID (ровно 22 символа, кроме чисто числовых) и Deezer ID (числа).
2. Если введен **Spotify ID / URL**:
   - Бэкенд запрашивает имя через клиент Spotify (если ключи активны).
   - Если ключей нет, используется резервное авторазрешение (или ID используется как временное имя).
   - На основе полученного имени выполняется мгновенный поиск в Deezer для сопоставления и сохранения `deezer_id`.
3. Если введен **Deezer ID / URL**:
   - Бэкенд получает имя из Deezer.
   - Выполняет поиск по этому имени в Spotify (если ключи активны) для заполнения `spotify_id`.
4. Если введено **обычное имя**:
   - Запрашивается Deezer API (лимит 8 результатов).
   - Для каждого результата в фоновом режиме (при наличии ключей) ищется пара на Spotify.
5. Возвращается обогащенный массив результатов с заполненными `spotify_id` и `deezer_id` для каждого совпадения.

## 🚀 Установка и запуск

### Зависимости:
Проект написан на **Python 3**. Для конвертации скачанных треков в формат `.mp3` на вашем компьютере должен быть установлен **ffmpeg** (путь к нему должен быть прописан в системной переменной PATH, либо исполняемый файл должен лежать в корне проекта).

### Установка библиотек:
```bash
pip install -r requirements.txt
```

### Запуск приложения:
```bash
python3 app.py
```
Сервер запустится по адресу `http://127.0.0.1:5000/` и автоматически откроет вкладку в вашем браузере по умолчанию.

#### Быстрый запуск кликом (на Windows и Linux):
- `run.bat` (Windows) или `run.sh` (Linux / macOS) — только запускают **`start.py`**.
- `start.py` сам проверяет канал, качает zip нужной ветки с GitHub (**git не нужен**), ставит зависимости и стартует `app.py`.

Канал обновлений — **`update_channel.txt`** в корне:

```
# stable  — только ветка main
# beta    — самая новая ветка на GitHub (по дате последнего коммита)
stable
```

## 📁 Папка пользовательских данных (`data/`)

При обновлении программы вы можете свободно заменять файлы кода, оставляя папку `data/` нетронутой — все ваши настройки сохранятся.

* **`translations/`** — Файлы локализаций (например, `RU-Russian.txt`, `EN-English.txt`). Формат файлов: `id:текст`.
* **`artists.txt`** — Простой текстовый список артистов (по одному на строку). Можно писать как имена, так и вставлять ссылки. Автоматически синхронизируется с `config.json`.
* **`blacklist.txt`** — Список слов-исключений для YouTube (по одному на строку). Видео с этими словами (например, `remix`, `live`, `cover`) будут игнорироваться.
* **`save_folder.txt`** — Путь к папке для сохранения скачанных треков.
* **`config.json`** — Системный файл конфигурации.
* **`library.json`** — База логического дерева альбомов, треков и статусов.
* **`tracks.db`** — База данных SQLite с историей загрузок.
