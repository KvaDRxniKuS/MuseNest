# 🎵 MuseNest (Версия 0.1 - Минимально Рабочая)

Мощный кроссплатформенный инструмент для автоматического мониторинга дискографий любимых артистов в музыкальных базах данных (**Deezer**, **Spotify**, **MusicBrainz**, **Яндекс Музыка**, **Zvuk**), умного поиска лучших аудиозаписей на **YouTube** (с фильтрацией по длительности, стоп-словам) и локальной загрузки в **MP3** высокого качества.

## 🚀 Нововведения в Версии 0.3.4 (Лог Изменений)

* **Сообщение об отказе Zvuk больше не противоречит само себе.** Строка из реального лога:

  ```
  Zvuk отказал в потоке (HTTP 403) — это качество недоступно для вашей
  подписки/региона, и анонимный mid тоже не отдан. Пробовал: mid (аноним) → HTTP 403.
  Токен не задан — без него Zvuk отдаёт только mid.
  ```

  В ней было три взаимоисключающих утверждения: `mid` только что получил `403`, но
  ниже обещалось, что «без токена Zvuk отдаёт только mid»; подпись винилась при
  том, что токена нет вообще (значит, и подписки нет); «тоже» подразумевало
  предыдущую попытку, хотя `mid` был единственной.
* **Нет токена + 403** → «Zvuk отказал в потоке (HTTP 403) — без токена этот трек не
  отдаётся. Добавьте токен: …» — указывается единственное рабочее действие вместо
  выдуманной причины про подписку/регион.
* **Нет токена + 401** → «Zvuk отклонил анонимный доступ (HTTP 401) …». Раньше эта
  ветка срабатывала и без пользовательского токена, требуя «обновить» токен,
  которого не существует — отклонён был анонимный.
* **Токен есть** → поведение прежнее: `401` = «Токен Zvuk истёк или неверен»,
  `403` = «недоступно для вашей подписки или региона».
* **Тесты**: `tests/test_zvuk_stream.py` — 21 → 25 проверок. Добавлены регрессии на обе
  ветки без токена и страховки в обратную сторону (настоящий истёкший токен и
  настоящая подписка по-прежнему называются своими именами).

## 🚀 Нововведения в Версии 0.3.3 (Лог Изменений)

* **«Проверить загрузчик» (Zvuk) больше не путает истёкший токен с неработающим API.**
  Оба шага проверки делали **один и тот же** аутентифицированный вызов `/api/tiny/profile`,
  поэтому истёкший токен отвечал `401`, и проверка рапортовала
  «Zvuk API недоступен (нужен VPN/прокси)» — то есть несуществующую аварию.
  При этом сам шаг проверки токена был недостижим (`if has_token and api_reachable`),
  поэтому `token_valid` никогда не мог стать `False` — проверка токена фактически не работала.
* **Доступность API теперь проверяется анонимно** (`token=None`), а валидность токена —
  отдельным явным запросом. В `_tiny()` появился параметр `token`
  (`_UNSET` = как раньше, `None` = без токена, строка = конкретный токен).
* **Понятные исходы проверки**:
  * токен истёк/неверен → «Токен Zvuk истёк или неверен (HTTP 401)… Скачивание продолжит
    работать только в качестве mid» + инструкция, где взять новый;
  * реальная авария → «Zvuk API недоступен» с пометкой, что проверка шла анонимно,
    значит дело в сети/прокси/DNS, а не в токене;
  * токен активен → «токен активен, качество: high».
* В результат добавлены поля `api_status` и `token_status` (HTTP-коды) для точной диагностики.
* **Тесты**: `tests/test_zvuk_downloader_check.py` — 8 проверок, включая ключевую регрессию
  (401 на токене ≠ «API недоступен»), настоящую аварию сети и `503` от сервера.

## 🚀 Нововведения в Версии 0.3.2 (Лог Изменений)

* **Zvuk больше не падает на весь трек, если высокое качество недоступно**: раньше
  `get_stream_url()` запрашивал `high` и при отказе молча возвращал `None`, из-за чего
  трек уходил на YouTube. Теперь работает **лесенка качества**: запрошенное (`high`/`flac`)
  → `mid`, то есть трек скачивается напрямую с Zvuk в доступном качестве, а в лог пишется
  предупреждение «отдано в качестве 'mid' вместо 'high'».
* **Истёкший токен больше не роняет загрузку**: на `HTTP 401` код повторяет запрос
  с анонимным токеном, а последующие ступени качества сразу идут с анонимным — протухший
  токен не отправляется повторно (меньше лишних запросов и риска лимитов).
* **Скачивание идёт тем же токеном, который отдал поток**: если поток получен анонимно,
  файл тянется анонимным токеном, а не истёкшим пользовательским.
* **Честные сообщения об ошибках вместо угадывания**: прежний текст
  «Без токена доступен только анонимный mid — этот трек требует подписку» был захардкожен
  и **врал**, когда токен задан (а качество `high` выбирается именно при заданном токене).
  Причина проглатывалась в `except Exception: return None`. Теперь ошибка содержит реальные
  коды и трассу попыток, например:
  `Токен Zvuk истёк или неверен (HTTP 401)… Пробовал: high (токен) → HTTP 401; high (аноним) → HTTP 403; mid (аноним) → ok. Токен задан.`
  Отдельно различаются: истёкший токен (401), отказ подписки/региона (403),
  сеть/прокси/DNS (нет ни одного ответа), и «200 без поля `stream`» — с показом формы ответа.
* **Токен не попадает в логи**: значение `X-Auth-Token` намеренно не кладётся в трассу
  попыток (проверяется отдельным тестом).
* **Строка лога остаётся читаемой**: сырой текст `requests` при сетевом сбое
  (`HTTPConnectionPool(...) Max retries exceeded ...`) сворачивается в короткую метку —
  «нет соединения» / «таймаут» / «DNS не резолвится» / «прокси не отвечает» / «ошибка TLS»,
  а причина называется один раз, а не по разу на каждое качество:
  `Zvuk недоступен (нет соединения) — до /api/tiny/track/stream не дошёл ни один запрос. Пробовал качества: high, mid. Токен задан.`
  Полный текст сохраняется в `ZvukStreamError.detail` для отладки.
* **Понижение качества видно в логе**: если запрошен `high`, а отдан `mid`, пишется
  предупреждение с именем артиста/трека и обоими качествами.
* **Тесты**: `tests/test_zvuk_stream.py` — 21 проверка на локальном стенде, отвечающем как
  Zvuk (401/403/200 без `stream`), включая точный сценарий из лога
  (`id=3862635281`, `quality=high`), отсутствие утечки токена и ограничение длины строки лога.
  Отдельно проверяется, что **сам файл** качается рабочим токеном: после восстановления по
  анонимному токену на загрузку аудио уходит именно он, а не протухший пользовательский
  (иначе фикс был бы косметическим — `resolve_stream` восстанавливался бы, а скачивание
  снова падало на 401).
  `tests/test_monitor_zvuk_downgrade.py` — 6 проверок предупреждения о понижении качества.

* **Переводы**: подписи стадий добавлены в `data/translations/RU-Russian.txt` и `EN-English.txt`
  (ключи `ytCheckStage_*`), при их отсутствии используются встроенные подписи.

## 🚀 Нововведения в Версии 0.3.0 (Лог Изменений)

* **Тестер yt-dlp / VPN** — новый инструмент для диагностики «почему YouTube не качает через мой VPN».
  Сравнивает **несколько конфигов VPN/прокси за один запуск** и по каждому показывает:
  какой IP/страну/провайдера видит YouTube, доступен ли youtube.com, работает ли извлечение метаданных
  и поиск `ytsearch` (ровно тот путь, которым MuseNest ищет треки), реально ли скачивается аудио
  и с какой скоростью (детект «задушенной» загрузки), а опционально — и боевой путь конвертации в mp3.
* **Понятные вердикты вместо сырых ошибок**: `Sign in to confirm you're not a bot` → «YouTube требует вход»,
  `not available in your country` → «контент закрыт для страны VPN», `429` → «лимит запросов»,
  `ProxyError/tunnel connection failed` → «VPN не отвечает», `nsig extraction failed` → «скорость режется».
  К каждому вердикту — что делать (сменить ноду, включить cookies, обновить yt-dlp и т. д.).
* **Проверка player clients** (`web`, `android`, `tv`): частый случай, когда с VPN-IP `web` требует вход,
  а `android`/`tv` работают — тестер это показывает явно.
* **Два способа запуска**: страница **🛰 VPN-тестер** в веб-интерфейсе (или `http://127.0.0.1:5000/vpn-test`)
  и CLI `python tools/yt_vpn_test.py`. Отчёты сохраняются в `data/vpn_tests/` (папка в .gitignore),
  можно выгрузить markdown-таблицу и JSON.
* **Проверка состояния окружения**: `python tools/yt_vpn_test.py --check-env` показывает версию yt-dlp,
  наличие ffmpeg и PySocks. Сам yt-dlp умеет SOCKS5 без PySocks, но сторонние библиотеки — нет.
* **Тесты**: добавлен `tests/test_vpn_probe.py` (29 проверок: разбор профилей, классификация ошибок,
  вердикты, отчёты, живые проверки на заведомо мёртвом прокси).

## 🛰 Тестер yt-dlp / VPN (v0.3.0+)

### Веб-интерфейс
Кнопка **🛰 VPN-тестер** в шапке или напрямую `http://127.0.0.1:5000/vpn-test`.
В поле «Профили VPN» — по одному профилю на строку:

```
Нидерланды SOCKS5 = socks5://127.0.0.1:1080
Германия HTTP, http://user:pass@1.2.3.4:8080
direct
```

`direct` — без прокси: запросы идут через текущий системный маршрут, то есть через тот VPN,
что включён в вашем VPN-клиенте. Переключайте ноды в клиенте и запускайте тест заново
(с разной «Меткой запуска»), чтобы сравнить ноды между собой.

### Командная строка

```bash
# сравнить текущий системный VPN и SOCKS5-прокси
python tools/yt_vpn_test.py --direct --proxy "NL SOCKS5=socks5://127.0.0.1:1080"

# проверить прокси, который уже задан в настройках MuseNest
python tools/yt_vpn_test.py --use-config-proxy --direct

# профили из файла + какие player clients выживают + сохранить отчёты
python tools/yt_vpn_test.py --profile-file vpn.txt \
    --url https://www.youtube.com/watch?v=dQw4w9WgXcQ \
    --clients web,android,tv --mp3 --json data/vpn_tests/last.json --md last.md

# быстрый режим (без скачивания и поиска) и только окружение
python tools/yt_vpn_test.py --direct --fast
python tools/yt_vpn_test.py --check-env
```

Код возврата `0` — все профили в вердикте `ok`/`throttled`, иначе `1` (удобно для скриптов/CI).

### Как читать результат

| Вердикт | Что означает | Что делать |
|---|---|---|
| ✅ Работает полностью | IP виден, поиск и скачивание в норме | можно пользоваться этим VPN |
| ⚠️ Работает, но скорость режется | YouTube душит поток (обычно < 60 кбит/с) | обновить yt-dlp, попробовать `socks5h://`, другую ноду |
| ⛔ YouTube требует вход с этого IP | «Sign in to confirm you're not a bot» | включить cookies YouTube или сменить страну |
| ⛔ Контент закрыт для страны VPN | гео-ограничение | выбрать US/DE/NL |
| ⛔ IP заблокирован / лимит 429 | нода в чёрном списке или перегружена | сменить ноду, снизить частоту сканирования |
| ❌ VPN/прокси не работает | прокси не отвечает, DNS/TLS сбои | проверить порт VPN-клиента, DNS, socks5h:// |

## 🚀 Нововведения в Версии 0.2.7 (Лог Изменений)

* **Zvuk: анонимное скачивание теперь работает (mid-качество)**: Раньше при отсутствии токена Zvuk-треки падали с `No Zvuk stream URL available (need subscription + token)`, потому что запрос к `/api/tiny/track/stream` шёл **без** `X-Auth-Token`. Теперь даже без подписки автоматически берётся **анонимный токен** через `/api/tiny/profile` и подставляется в запрос потока — доступно mid-качество. С токеном по-прежнему `high`/`flac`.
* **Фоллбэк на YouTube при сбое Zvuk**: Если прямой Zvuk-путь не смог отдать поток (нет токена/подписки/гео-блок/DRM), загрузка **пробует YouTube** по имени «артист — трек» вместо мгновенной ошибки. Это касается и обычной, и форс-загрузки. Если YouTube тоже не нашёл — в ответе показываются **обе** причины (`YouTube: … (Zvuk: …)`), чтобы было ясно, что именно пошло не так.
* **Итог для треков из каталога Zvuk**: без токена: скачается напрямую с Zvuk (mid) → если не вышло, с YouTube; с токеном: Zvuk (high/flac) → при сбое YouTube.

  * **⬇️ Основной загрузчик** — откуда качается аудио: YouTube (yt-dlp) или Zvuk (прямое скачивание) (`downloader`).

Они переопределяют глобальные значения для конкретного артиста (поля `source` / `downloader` у артиста в `config.json` / `library.json`). Значение `auto` означает «как в глобальных настройках».
* **Маршрутизация загрузки**: Трек с ID `zvuk-...` всегда качается напрямую с Zvuk (только Zvuk умеет его отдать). Обычные треки идут в выбранный загрузчик: YouTube-поиск+скачивание либо прямое Zvuk-скачивание. При выборе Zvuk-загрузчика для артиста без `zvuk-` ID вернётся понятная ошибка (нет потока / нужен токен).

   - **Логические ссылки:** В интерфейсе этот трек будет светиться зелёным (скачанным) во всех альбомах и синглах, где он присутствует, не занимая лишнего места на диске.
   - **Авто-сортировка и чистка:** Скрипт автоматически находит старые файлы (в корне или папках синглов), переносит их в новые папки альбомов, а опустевшие папки синглов удаляет.
   - **Решение проблемы маятника:** Логика приоритетов построена по нормализованному имени трека, что исключает бесконечный перенос файлов туда-сюда из-за разных ID релизов на сервисах.

3. 🚀 **Многопоточность нового поколения:**
   - **Параллельная загрузка:** Поиск на YouTube и скачивание треков выполняются параллельно (до 8 потоков в соответствии с настройками).
   - **Параллельный сканер (в 6 потоков):** Сбор треков и альбомов из сети Deezer/Spotify оптимизирован через пул потоков, благодаря чему дискография любого артиста собирается за 1–2 секунды вместо полуминуты.

4. 🌍 **Полная расширяемая локализация (RU / EN / Кастомные языки):**
   - Удобный выпадающий список выбора языков прямо в шапке интерфейса (выбор запоминается в браузере).
   - Все тексты (включая настройки, источники, плейсхолдеры и логи) полностью переведены.
   - **Кастомные переводы:** Пользователи могут самостоятельно создавать новые локализации, просто скопировав любой файл в `data/translations/` (например, создав `DE-Deutsch.txt`).
   - **Каскадный фоллбэк:** Если в пользовательской локализации пропущен какой-то ключ, интерфейс автоматически и безопасно подставит английский вариант — никаких пустых строк или ошибок в UI.

5. 🔴 **Интерактивная диагностика ошибок (`ERR-1` — `ERR-5` + подробный TODO-лист):**
   - Если трек не прошел фильтры, он загорается **тонкой красной обводкой** с кодом ошибки:
     - **`ERR-1`** — Не найдено подходящих результатов на YouTube.
     - **`ERR-2`** — Не подошло по времени (длительность отличается от оригинала больше допуска).
     - **`ERR-3`** — Отфильтровано стоп-листом блек-листа.
     - **`ERR-4`** — Ошибка загрузки или конвертации (обрыв соединения, блокировка YouTube).
     - **`ERR-5`** — Сетевой сбой или жесткий лимит запросов YouTube.
   - **Всплывающий TODO-список:** При наведении курсора на код ошибки выводится подробная пошаговая инструкция на выбранном языке, как решить эту конкретную проблему.

6. ⏹ **Экстренная мгновенная остановка:**
   - Прерывание текущего сканирования и загрузок в один клик. Работает молниеносно благодаря перехватчику логов `YtDlpAbortLogger` и progress-hook, выбрасывающим прерывание прямо внутри `yt-dlp`.

## 🛠️ Техническое описание архитектуры (для будущих разработчиков)

Инструмент построен по модульному принципу на связке **Flask (бэкенд)** и **Vanilla JS (фронтенд)**.

### 1. Архитектура работы с источниками (`core/source.py`, `core/spotify.py`)
- **`DeezerSource`**: Не требует авторизации. Использует общедоступное API `https://api.deezer.com`. Служит основным стабильным поисковым шлюзом по умолчанию. Извлекает число подписчиков (`nb_fan`).
- **`SpotifyClient`**: Работает через официальное API `https://api.spotify.com/v1`. Требует выполнения OAuth Client Credentials (`_auth()`). Если авторизация падает с ошибкой (например, из-за пустых/неверных ключей), это перехватывается на уровне роутера API и не приводит к падению бэкенда.
- **`MultiFallbackSource`**: Умный агрегатор источников. Сначала опрашивает Spotify (если авторизован), затем Deezer, и в крайнем случае — базу MusicBrainz.

### 2. Спецификация хранения артистов (`data/config.json` и `data/library.json`)
В версии 0.1.7 каждый артист в конфигурационном файле имеет следующую структуру:
```json
{
  "id": "spotify_id_или_deezer_id_или_имя",
  "name": "Официальное имя артиста",
  "source": "deezer",  // Источник для мониторинга: "spotify" или "deezer"
  "spotify_name": "Имя в Spotify", 
  "spotify_id": "46P740d5P5uXbS6nCq0lS7", // Уникальный 22-значный Base62 ID
  "deezer_id": "15100095",                // Числовой ID Deezer
  "genre_path": "Rock/Metal"              // Опциональный путь подпапок
}
```

Файл `library.json` хранит в себе снимок структуры дискографии артистов (альбомы, треки, длительность, флаги `downloaded`, `ignored`, `no_match` и коды ошибок `error_code`), которая динамически обновляется из выбранного источника.

### 3. Логика API Поиска (`/api/artist_search`)
Когда пользователь отправляет поисковый запрос:
1. Выполняется парсинг ввода (`src_mod.parse_input`). Распознаются регулярными выражениями ссылки Spotify, Deezer, чистые Spotify ID (ровно 22 символа, кроме чисто числовых) и Deezer ID (числа).
2. Если введен **Spotify ID / URL**:
   - Бэкенд запрашивает имя через клиент Spotify (если ключи активны).
   - Если ключей нет, используется резервное авторазрешение (или ID используется как временное имя).
   - На основе полученного имени выполняется мгновенный поиск в Deezer для сопоставления и сохранения `deezer_id`.
3. Если введен **Deezer ID / URL**:
   - Бэкенд получает имя из Deezer.
   - Выполняет поиск по этому имени в Spotify (если ключи активны) для заполнения `spotify_id`.
4. Если введено **обычное имя**:
   - Запрашивается Deezer API (лимит 8 результатов).
   - Для каждого результата в фоновом режиме (при наличии ключей) ищется пара на Spotify.
5. Возвращается обогащенный массив результатов с заполненными `spotify_id` и `deezer_id` для каждого совпадения.

## 🚀 Установка и запуск

Проект написан на **Python 3**. Для конвертации скачанных треков в формат `.mp3` на вашем компьютере должен быть установлен **ffmpeg** (путь к нему должен быть прописан в системной переменной PATH, либо исполняемый файл должен лежать в корне проекта).

```bash
pip install -r requirements.txt
```

```bash
python3 app.py
```

- `run.bat` (Windows) или `run.sh` (Linux / macOS) — только запускают **`start.py`**.

# stable  — только ветка main
# beta    — самая новая ветка на GitHub (по дате последнего коммита)
stable

## 📁 Папка пользовательских данных (`data/`)

При обновлении программы вы можете свободно заменять файлы кода, оставляя папку `data/` нетронутой — все ваши настройки сохранятся.

* **`translations/`** — Файлы локализаций (например, `RU-Russian.txt`, `EN-English.txt`). Формат файлов: `id:текст`.
* **`artists.txt`** — Простой текстовый список артистов (по одному на строку). Можно писать как имена, так и вставлять ссылки. Автоматически синхронизируется с `config.json`.
* **`blacklist.txt`** — Список слов-исключений для YouTube (по одному на строку). Видео с этими словами (например, `remix`, `live`, `cover`) будут игнорироваться.
* **`save_folder.txt`** — Путь к папке для сохранения скачанных треков.
* **`config.json`** — Системный файл конфигурации.
* **`library.json`** — База логического дерева альбомов, треков и статусов.
* **`tracks.db`** — База данных SQLite с историей загрузок.
